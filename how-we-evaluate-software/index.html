How We Evaluate Software

{% include byline.html %}

OpenSourceFeed's software section covers open source tools and the proprietary software people want to replace. This page explains where the facts on each page come from, how we decide what counts as an alternative, and how pages are kept current.

What "open source" means here

A tool is labelled Open Source only if its code is released under an OSI-approved open source license, such as the GPL, MIT, Apache, or MPL licenses. Software whose code is public but whose license restricts use (for example, a non-commercial or "community" license that isn't OSI-approved) is labelled Source Available instead, and everything else is Proprietary. Where a project mixes licenses, for instance an open source core with a proprietary enterprise edition, the software page says so next to the license.

Where the facts come from

  • License: the project's own license files or official website. The "At a glance" panel links to the license text.
  • Source code: the project's official public repository, linked from the software page. We confirm each repository link resolves before listing it.
  • Latest version: the newest stable release tag in that repository, ignoring alpha, beta, and release-candidate tags. Each version shows the date it was checked, because versions change faster than the rest of the page.
  • Platforms: the operating systems the project officially ships or supports.
  • Developer: the company, foundation, or community that maintains the software.

How we choose alternatives

An "alternatives" page lists open source tools that cover the main job the proprietary product is used for. To be included, a tool must be under an OSI-approved license (or be clearly labelled when it isn't) and be actively maintained. We describe what each alternative is best for, what you gain, and what you give up compared with the original. When only one or two mature open source options exist, the page says so rather than padding the list.

How roundups are ranked

"Best open source" roundups list our picks in order. The order reflects maturity, how actively a project is maintained, platform coverage, and how well it suits most people in that category; each pick notes who it is best for. The comparison table on each roundup is generated from the same data as the software pages, so the two never disagree.

Keeping pages current

Every page shows when it was last updated, and that date changes only when the content does. Version numbers carry their own check date. We review pages that start to lose search visibility or that cover fast-moving products first.

Corrections

If something on a page is wrong or out of date, email contact.opensourcefeed@gmail.com with the page link and a source, and we'll fix it.
